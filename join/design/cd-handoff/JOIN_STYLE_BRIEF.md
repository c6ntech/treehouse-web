## 1. 這頁在做什麼（一句話）

單頁、行動優先，Beta 招募轉換頁。核心資訊密度原則：**一個數字（報名人數）+ 一個動作（CTA）+ 其餘全部收起**。傳播主要靠截圖轉發到群組，不是靠點連結——這點決定了首屏必須自成一張完整的圖。

## 2. 最不能妥協的結構限制

- **手機第一屏（不需捲動）必須同時看到**：品牌、slogan、報名人數、單一 CTA。這是唯一的「螢幕高度預算」硬限制——這四個元素之間怎麼分配視覺重量、間距節奏，你決定；但四個都要在場，且不能要求使用者捲動才看到。
- **主 CTA 只能有一個**，不能出現第二個視覺上會競爭注意力的按鈕。
- 報名人數是「看板／招牌」感的視覺物件，不是一行普通統計文字——具體造型不限，但要讓人一眼認出「這是這一頁的主視覺焦點」。數字本身要夠大。
- 「Treehouse 怎麼玩」四張圖用橫向滑動呈現（類似 IG 輪播貼文的手感），位置在第一屏「之後」，不能拖慢或搶走首屏的視覺重量。

## 4. 互動模型（邏輯已寫好，只需要調視覺回饋，不用改行為）

- 數字變動：輕微滾動／計數動畫，不浮誇，需尊重 `prefers-reduced-motion`（此時直接跳到終值，不做動畫）
- 輪播：手機原生手勢橫滑，桌機拖曳或箭頭按鈕，圓點會自動同步目前頁面
- CTA：點擊開新分頁到表單
- 「沒有免費版本」：點擊展開／收合

## 5. 技術骨架 — 這些 class／id 是資料綁定，視覺調整請透過 CSS，**不要改名稱或移除元素**

| 元素 | id / class | 用途 |
|---|---|---|
| 報名人數數字 | `#signupNumber` | JS 直接寫入 textContent，做計數動畫 |
| 主 CTA | `#ctaButton` | JS 動態改寫 href（帶 UTM）、綁 click 事件 |
| 輪播容器 | `#howTrack`、`.how__slide` ×4 | scroll-snap 容器與四張投影片 |
| 輪播圓點 | `#howDots` 內的 4 個 `<button>` | JS 綁點擊跳頁、`aria-current` 同步 |
| 輪播箭頭 | `.how__arrow--prev` / `.how__arrow--next` | 桌機用，手機預設隱藏 |
| 男女比例條 | `#genderRatio`、`#genderFemaleBar`／`#genderMaleBar`、`#genderFemalePct`／`#genderMalePct` | JS 寫入寬度百分比與文字 |
| 定價區塊 | `#pricingSection`、`#pricingToggle`、`#pricingBody`、`#pricingAmount`／`#pricingTrial` | 展開/收合邏輯、金額與天數由 config 寫入 |
| 倒數 | `#countdownSection`、`#countdownDays` | JS 每分鐘更新剩餘天數 |

旗標關閉的區塊（6、8、9 對應的元素）目前帶有 `hidden` 屬性，`hidden` 屬性本身不要拿掉——那是 config 旗標控制的，設計稿可以假設「旗標開啟時長這樣」來出圖，但實作接回去時這個機制要保留。

若視覺方案需要新增額外的 DOM 節點（例如看板造型需要額外裝飾用的 `<span>`），可以加，但上面列的既有 id 要維持在原本的元素上，不要搬到別的節點。

## 6. 硬限制（沿用全站 `design/cd-handoff/STYLE_BRIEF.md` 的既有約定，這裡重申跟本頁相關的部分）

- **零外連資源**：全站慣例是所有字體／圖片／CSS／JS 都自架，不接外部 CDN。本頁唯一例外是 GA4（`gtag.js`），已經是記錄在案、只在設定 ID 時才載入的例外，不要因為視覺需求又加其他外連資源（自架字體／圖片都可以，只是不能外連）。
- **純靜態、無 build**：CSS／JS 是手寫檔案，沒有建置流程，交回的東西要能直接貼進 `assets/join.css`。
- **webview 相容**：App 內建瀏覽器、LINE／Threads 內建瀏覽器都要能正常顯示，避免用支援度差的新 CSS 特性。
- **手機優先，≤360px 不可破版**。
- **無障礙**：focus ring 要看得到、skip-link 保留、文字對比度 ≥ WCAG AA、圖片要有 alt、輪播圓點是真的可點擊的 `<button>`（不是純裝飾）。
- **效能**：輪播四張圖目前已壓到每張 ≤40KB（WebP，依高度限制縮放）。如果視覺方案需要換版型或重新裁切，麻煩比照這個量級，不要退回原始 1–2MB 的 App Store 截圖尺寸。
- **輪播的水平定位不要用 `scrollIntoView`**：即使給 `block:"nearest"`，只要投影片比視窗高（手機上一定是），瀏覽器仍會連帶垂直捲動整份文件——實測 390×844 載入後頁面自己停在 `scrollY:151`，把品牌／字標／slogan 推出首屏，直接違反第 2 節那條硬限制。已改成只寫 `track.scrollLeft`（`join.js` 的 `centerSlide()`）。若視覺方案要改輪播的對齊方式，請沿用同一個做法。
